# 申し送りメーカー（職場実運用版・完全オフライン）

介護・医療現場の「申し送り・勤務記録」を、**そのPCの中だけ**で作成・保存・検索・印刷するための単一HTMLアプリです。

- ファイルは [`index.html`](index.html) **1つだけ**（ビルド不要・インストール不要・依存パッケージなし）
- データはブラウザの localStorage にのみ保存
- **外部サーバー・外部AI・外部CDN・外部フォント・解析への通信は一切ありません**

> このリポジトリにはアプリ本体のコードだけを置きます。
> **実在する入居者・患者の個人情報や、実運用データは絶対に置きません。**
> 実運用のデータ入力は職場のPC内だけで行います。

---

## 使いはじめかた（職場PC）

1. `index.html` を職場PCの決まった場所（例：デスクトップの「申し送り」フォルダ）へ置く
2. ダブルクリックでブラウザ（Edge / Chrome）で開く
3. デスクトップかタスクバーへショートカットを作り、**毎日そこから開く**

インターネット接続は不要です。オフラインでも全機能が動きます。

> **毎日、同じPC・同じブラウザ・同じ場所のファイルから開いてください。**
> データはHTMLファイルの中ではなく、そのPCのブラウザ内に保存されます。
> 別のブラウザで開くと、別の保存場所になり「データが消えた」ように見えます。

## 画面（5つのタブ）

| タブ | できること |
| --- | --- |
| **入力** | 毎日つづく大事なこと／本日の申し送り／記録・バイタル／予定の追加。すべて自動保存 |
| **入居者** | 入居者の追加・並べ替え・空床・退居／復帰、記録項目の設定、バックアップ |
| **予定** | 毎週くりかえす定期予定の登録、1回だけの予定の一覧・別紙印刷 |
| **印刷** | A4横の申し送り用紙のプレビューと印刷 |
| **さがす** | 過去の申し送り・記録・予定を横断検索（入力途中に候補が出ます） |

## ユニット構成

| 区分 | 登録できる人数（上限） | 備考 |
| --- | --- | --- |
| 静養室 | 4 名 | 重症者などを一時的に管理する独立枠。画面上でも点線で区別 |
| ユニット2 | 34 名 | 余裕をもたせた上限 |
| ユニット3 | 30 名 | 同上 |
| ユニット4 | 30 名 | 同上 |
| ユニット5 | 30 名 | 同上 |

入居中の方を静養室へ一時的に移すときは、「入居者」タブの一覧にある **「いる場所」** から選び直します
（登録し直す必要はなく、過去の申し送り・記録・予定はそのまま残ります）。

上限を変えたいときは `index.html` の `UNIT_DEFS` の `max` を書き換えるだけです（1か所）。

```js
var UNIT_DEFS = [
  { id:1, label:"静養室",    max:4,  rest:true },
  { id:2, label:"ユニット2", max:34 },
  ...
];
```

## 印刷（A4横・1ユニット＝1枚）

- **静養室が0人のとき：ユニット2・3・4・5 の 4枚**
- **静養室に1人以上いるとき：静養室・ユニット2・3・4・5 の 5枚**（静養室が先頭）
- 静養室が0人へ戻れば、自動的に4枚構成へ戻ります
- 各ユニットは必ず別ページ。次のユニットの内容が前のページへ混ざりません
- 人数に応じて文字サイズが自動で段階変更されます（34名でも1枚に収まります）
- 入りきらない人がいる場合は、プレビュー下に「要確認」として名前が出ます（内容は勝手に削りません）
- 見本の入居者・空床・退居は、人数にも印刷にも含まれません

## 毎週くりかえす予定（定期予定）

曜日と勤務帯を一度登録すれば、その曜日が来るたびに自動で用紙へ出ます。

| 勤務帯 | 出る用紙 |
| --- | --- |
| **日勤** | 実施する**その日**の用紙の【日勤】欄 |
| **夜勤** | 夜勤者が前もって確認できるよう、実施日の**前日**の用紙の【夜勤】欄 |

例：

- 毎週**月曜**の夜勤（BS測定） → **日曜**の用紙の夜勤欄
- 毎週**火曜**の夜勤 → **月曜**の用紙の夜勤欄
- 毎週**日曜**の夜勤 → **土曜**の用紙の夜勤欄

前日の計算は曜日の文字列ではなく**日付計算**で行うため、月末・年末年始・うるう年をまたいでも正しく出ます。

定期予定は「毎週◯曜日」という**ルールだけ**を保存し、表示する日付は毎回計算します。
そのため画面を開き直しても**予定が増えたり二重登録されたりしません**（長期運用でもデータが肥大化しません）。
1回だけの予定（受診・外出など）とは内部で別データとして区別しています。

## オフライン文章整形

短い入力や箇条書きを、申し送りとして読みやすい文章へ整えます。

```
発熱 38.0 カロナール服用 水分摂取
        ↓ 「文章を整える」
発熱38.0℃。カロナール服用。水分摂取。
```

- 単語だけ／短文／箇条書き／まとまりのない文章／長文に対応
- 辞書・キーワード解析・定型変換による**完全ローカル処理**（外部AI APIは使用しません）
- 転倒・誤嚥・全介助・2人介助・トロミ・アレルギー・禁忌などの語は**絶対に落としません**（落ちる場合は整形せず元の文章を返します）
- 無駄に長くしません（整形後が元より長くなる場合は整形しません）
- 「元にもどす」で整える前の文章へ戻せます

> 医学的判断・診断・投薬判断・緊急度判定は行いません。
> 入力された事実を読みやすく並べ直すだけです。判断は必ず職員・医療者が行ってください。

## 操作の見本（架空の入居者4名）

初期状態では実在の入居者は登録されていません。代わりに、操作の見本として**完全な架空の4名**がユニット2〜5に1名ずつ入っています。

| ユニット | 見本 | 内容 |
| --- | --- | --- |
| 2 | 見本 花子 | 発熱・服薬・水分・食事の記録例 |
| 3 | 見本 太郎 | BS／ターゲス／定期予定（日勤・夜勤）の例 |
| 4 | 見本 みどり | トロミ・誤嚥注意・独自項目（水分量・排便）の例 |
| 5 | 見本 一郎 | 処置・移乗2人介助・受診予定の例 |

見本は**実データとして扱いません**。

- 実際の登録人数に含めない／印刷に載せない／予定一覧に載せない
- 集計に含めない／「さがす」の結果に出さない
- 申し送り・記録は日次データとして保存されず、入居者データの中に持ちます

慣れたら「入居者」タブ →「管理する人だけが使う操作」→「見本の入居者4人をまとめて削除」で削除できます。

## データの保存とアプリの更新

### 保存

- 保存先：ブラウザの localStorage（キー **`kaigo_handover_v2`**）
- 入力・修正はすべて自動保存（保存ボタンはありません）
- 保存できないときは画面上部に赤い警告が出ます
- 保存するのはテキスト・数値・日付・時刻のみ。画像・音声・動画は扱いません

### アプリを更新しても過去データを失わない設計

今後「職場で使用 → フィードバック → 自宅で修正 → 新しい index.html を職場PCへ導入」を繰り返す前提です。

- **保存キー `kaigo_handover_v2` は変更しません**（変更するとデータが読めなくなるため）
- データ構造を変えるときは `DB.v`（データ版数）を上げ、`migrate()` で旧形式を**非破壊的に**新形式へ補完します
- `migrate()` は既存の値を書き換えず、足りないものだけ補い、何度実行しても同じ結果になります

更新手順：

1. 念のため「バックアップを保存」
2. 古い `index.html` を新しい `index.html` で置きかえる（同じ場所・同じファイル名）
3. いつものブラウザで開く → 入居者・申し送り・記録・予定・定期予定はそのまま

**アプリを削除したり、ブラウザのデータを消したりする必要はありません。**

### バックアップ・復元

- 「入居者」タブ →「バックアップを保存」でJSONファイルをこのPCへ保存
- 「バックアップから戻す」で復元（実行前に、現在データの保存を確認します）
- ファイルが壊れている／形式が違う場合は**復元を中止し、いまのデータをそのまま残します**
- 危険な操作（完全削除・一括削除）はすべて確認ダイアログ付き

> **取扱注意：** バックアップファイルには氏名・部屋番号・申し送り・記録が含まれます。
> 保存場所・持ち出し・廃棄は施設の規定に従ってください。
> このリポジトリへは絶対にコミットしないでください（`.gitignore` で `*.json` を除外しています）。

## 完全オフライン

このアプリには、通信・送信を行う処理が**1件も実装されていません**。

- 送信系ブラウザAPI（通信・計測・ソケット等）の記述：**0件**
- 外部script / 外部stylesheet / 外部フォント / 外部画像 / 外部CDN：**0件**
- `http://` `https://` で始まるURL：**0件**
- Analytics / Telemetry：**なし**

これらは [`tests/app.test.js`](tests/app.test.js) が実行のたびに自動検査します。

## テスト

### 1. ロジックのテスト（ブラウザ不要・依存パッケージなし）

```
node tests/app.test.js
```

`index.html` のインラインスクリプトをそのまま読み込んで、次を検証します。

1. ユニット構成・登録上限
2. 静養室の有無による印刷対象の自動切替（4ユニット／5ユニット）
3. 見本の入居者が実データに混ざらないこと
4. 定期予定（日勤＝当日／夜勤＝前日）と、月末・年末年始・うるう年をまたぐ計算
5. 定期予定が重複生成されないこと
6. 自動保存と、旧データ（v7）からの移行でデータを失わないこと
7. バックアップの形式検証（壊れたファイルで既存データを消さない）
8. オフライン文章整形（安全に関わる語を落とさない／医学的判断を足さない）
9. 外部通信のコードが0件であること

### 2. ブラウザでの動作確認（実際に描画して確認）

```
node tests/browser_check.js
```

`index.html` を **ローカルファイル（`file://`）として開いた状態**でヘッドレス Chrome / Edge に描画させ、次を確認します。

- 印刷枚数（静養室0人＝4枚／1人以上＝5枚／静養室が先頭／ユニットが混ざらない）
- 満床に近い人数（静養室4・U2:34・U3〜5:30＝計128名）で **1ユニットが1枚に収まる**こと
- 画面のボタン操作（入居者追加・文章を整える・元にもどす・予定登録・定期予定登録・検索・見本の削除）
- **静養室への移動**：既存の入居者を静養室へ移すと印刷が5枚構成へ、戻すと4枚構成へ切り替わること
- **アプリ更新**：旧版データが入ったブラウザで新しい `index.html` を開いても、入居者・申し送り・記録・予定が失われないこと
- **再読込**：ブラウザを閉じて開き直しても入力が残り、見本や定期予定が二重に作られないこと
- **Console エラーが0件**であること
- 実行中に通信APIが1度も呼ばれていないこと（fetch / XHR / WebSocket / sendBeacon を監視）

Chrome / Edge が見つからない場合は場所を指定できます。

```
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" node tests/browser_check.js
```

## 医療安全上の位置づけ

このアプリは申し送り・勤務記録を**整理して印刷する支援ツール**です。次のことは行いません。

- 診断・医学的判断
- 投薬判断・投与量判断・治療提案
- 緊急度判定の自動化

文章整形も、入力された事実を読みやすく整えるだけで、元の意味を勝手に変更・補完しません。
