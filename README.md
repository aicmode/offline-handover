# 申し送りメーカー

介護・医療現場の「申し送り・勤務記録」業務を想定して作成した、単一HTMLのWebアプリです。
HTML / CSS / JavaScript のみで構成され、データはブラウザの localStorage にのみ保存します。
**外部API・外部AI・サーバー送信・CDN読み込みは一切ありません。**

公開版は、リポジトリ**ルートの [`index.html`](index.html) 1ファイル**です。

| パス | 用途 |
| --- | --- |
| [`index.html`](index.html) | 公開版（ポートフォリオデモ）。**架空のデモデータ80名分**が入った状態で起動します |

ローカルで見る場合も、この `index.html` をブラウザで開くだけです（サーバー不要）。

---

## 作品概要・目的

紙の申し送り用紙を毎日手書きで作り直す運用を想定し、

- 前日の申し送りを引き継ぐ
- 入居者ごとに必要な記録項目だけを用紙へ出す
- A4横の用紙としてそのまま印刷する

という流れを、インストール不要・単一HTMLで完結させることを目的にしています。
ネットワークやセキュリティの制約が強い環境でも配置しやすいよう、**依存ライブラリ・ビルド工程を持たない構成**にしています。

---

## 主な機能

- 入居者マスター管理（追加・並べ替え・空床・**退居／復帰**・完全削除は二段階確認）
- ブロック（A〜Dの4ブロック）単位の管理
- 常設重要メモ（毎日引き継ぐ内容）／今日あったこと／本日の申し送り
- 前日申し送りの自動引継ぎ（**今日を初めて開いたときだけ**。過去日・未来日は閲覧しても生成しない）
- 前日・過去日からのコピー（未入力者のみ／1人ずつ確認して上書き）
- 記録・バイタル入力
  - T / P / BP / SpO2 / 食事（朝・昼・夕）/ Hr / **BS** / BW / メモ
  - 入力した値はそのまま用紙の記入線へ印字される
- 入居者ごとの記録項目設定（日勤／夜勤を個別にON/OFF、項目ごとの曜日指定）
  - ターゲスBS（1〜3回目）、**翌朝BS**（測定する朝の曜日を指定すると前日の夜勤欄へ自動表示）
  - 施設独自のカスタム項目（項目名・勤務帯・曜日・単位・入力欄サイズ）
- 予定管理（外出・外泊・受診・入院・退院・家族面会・行事・その他）
  - 「今日あったこと」からの予定候補抽出（自動確定はしない）
  - 予定一覧のA4横・**別紙**印刷
  - 過去予定の整理（自動削除はせず、確認してから削除）
- 履歴検索（日次データ・予定・常設重要メモを横断。退居者の履歴も検索可能）
- A4横印刷（**1ページ10名／各ブロック 表10名・裏10名**）
- JSONバックアップ保存・復元（復元前バックアップの導線と形式検証つき）
- 印刷欄に収まらない入力の実測検知と警告表示
- 検索できる「使い方」と、困りごと別「ヘルプ」を単一HTML内に収録

## 公開版（ルート `index.html`）

ポートフォリオとして公開するための構成です。**実際の職場環境とは完全に切り離しています。**

### 架空データのみを使用

- **A〜Dブロック 各20名・合計80名**の完全架空の入居者
- 部屋番号は `A-101〜A-120` / `B-101〜B-120` / `C-101〜C-120` / `D-101〜D-120`
- 申し送り・重要メモ・バイタル・BS・食事・水分・体重・予定もすべて架空
- 予定の場所は「デモ中央クリニック」「サンプル総合病院」など、**架空と分かる名称**のみ
- 実在の施設名・ユニット名・入居者名・職員名・IPアドレス・ネットワーク情報・医療機関名は
  コード・コメント・初期値のいずれにも含まれていません

> 表示される数値は画面確認用に生成した架空値です。**診断・医療判断には使用できません。**

### デモの動作

- 初回起動時のみ、80名分のデモデータを自動生成します
- 2回目以降は、**利用者が編集した内容をそのまま保持**します（リロードしても上書きしません）
- 画面上部の「**デモデータを初期化**」で、いつでも初期状態へ戻せます（確認ダイアログあり／キャンセル可）
- 閲覧専用ではありません。入居者追加・編集・退居／復帰・申し送り入力・重要メモ・バイタル入力・
  BS入力・予定追加／編集・履歴検索・日付変更・ブロック変更・印刷・バックアップ・復元が
  すべて公開版のまま操作できます

### 印刷レイアウト

- A4横（297×210mm）
- **10名ごとに改ページ**（11人目が中途半端に次ページへ送られない固定分割）
- 各ページに「ブロック名／表面・裏面／対象日／日勤・夜勤欄／人数／ページ番号」を表示
- 各ブロック20名の初期状態では **表10名＋裏10名 × 4ブロック = 合計8ページ**

## 使用技術・データ保存方式

- HTML / CSS / JavaScript（フレームワーク・ビルド工程・パッケージ依存なし）
- 単一HTMLファイル（スタイル・スクリプト・ドキュメントをすべて同梱）
- データ保存：**ブラウザの localStorage のみ**
  - 保存先はブラウザごと・ドメインごとに独立しています
- バックアップ：ローカルのJSONファイルへ保存／JSONファイルから復元

### 外部通信について

**「オンラインでページを配信していること」と「入力データをオンライン送信すること」は別物です。**

- ページ自体は静的ホスティングから配信されます
- 一方で、入力データは**サーバーへ送信されません**
- `fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` などの送信処理、
  外部DB・外部AI API・解析APIの呼び出しは**実装していません**
- 外部CDN・Webフォント・外部画像も読み込みません（サブリソース0件）

---

## 実運用について

要件に応じて、**オンライン版／オフライン版のどちらの構成にも対応できます。**

- オンライン版：静的ホスティングでURLを配信する構成
- オフライン版：同じ `index.html` を端末へ配置し、ネットワークなしで使用する構成

どちらもファイルは同一で、ビルドの切り替えは不要です（デモデータが不要な場合は、
入居者マスターから削除するか「デモデータを初期化」後に登録し直して運用します）。

ただし実際の導入方法は、**ネットワーク構成・セキュリティポリシー・端末の管理方針・
持ち出し可否・バックアップ運用**などによって異なります。
導入時はシステム管理者と要件を確認したうえで構成を選定する必要があり、
どのような環境でも必ず導入できるというものではありません。

## 公開・デプロイ

静的サイトとしてそのまま配信できます（サーバーサイド処理は不要です）。

### Vercel

リポジトリを Vercel にインポートするだけで公開できます。

- Framework Preset: **Other**
- Build Command / Install Command: **なし（空欄）**
- Output Directory: **リポジトリルート**
- ルート `/` は [`vercel.json`](vercel.json) の rewrite でルートの `index.html` を返します

以降は `main` ブランチへ push するたびに自動で再デプロイされます。

### GitHub Pages

Settings → Pages → Source を `main` / `root` にすると、
`https://<ユーザー名>.github.io/offline-handover/` でルートの `index.html` が公開されます。
