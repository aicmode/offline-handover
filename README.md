# 申し送りメーカー（ポートフォリオ公開デモ）

介護・医療現場の申し送り、記録、予定をひとつの画面でまとめ、検索・印刷・バックアップできるシングルHTMLアプリです。

> デモに表示される人物、部屋番号、申し送り、記録、予定はすべて架空です。
> 公開デモに実在する個人情報を入力しないでください。

## 解決する課題

- 日々の申し送りと記録が分散し、探すのに時間がかかる
- 人によって必要な記録項目・曜日・勤務帯が異なる
- データを外部サーバーへ送らず、端末内だけで扱いたい
- 手書き用のA4用紙を、人数や記録項目数に合わせて見やすく作りたい

## デモの構成

| ブロック | 初期デモ人数 | 最大人数 |
| --- | ---: | ---: |
| Aブロック | 15名 | 20名 |
| Bブロック | 12名 | 20名 |
| Cブロック | 18名 | 20名 |
| Dブロック | 16名 | 20名 |
| 合計 | 61名 | 80名 |

初回表示時だけ、61名の架空データを生成します。部屋番号は `A101`〜`D116` のような汎用形式です。再読込やブラウザ再起動で重複生成せず、各ブラウザの `localStorage` に変更を保持します。

## 主な機能

- A〜Dブロックの切り替え、追加、空床、退居、復帰、ブロック移動
- 毎日つづく大事なこと、本日の申し送り、日勤／夜勤の記録を自動保存
- 新規入居者の記録項目は初期OFF。人別・勤務帯別・曜日別に設定
- 記録項目をOFFにしても曜日設定を記憶し、再度ONにしたときに復元
- 1回だけの予定と、曜日・勤務帯を指定する定期予定
- 過ぎた予定は自動的に隠し、必要なときだけ再表示（データは削除しない）
- 氏名、部屋番号、申し送り、記録、予定の全ブロック検索
- 部分一致、表記ゆれ、関連語、年・月・日のうろ覚え検索
- 手動順、部屋番号順、五十音順、追加した順、最近編集した順の5種類
- 人数と内容量に合わせて行高を調整する Adaptive Row Height 印刷
- JSONバックアップの保存と復元
- 人数、保存、検索、印刷、バックアップに含まれない固定記入例
- 確認ダイアログ付きの「デモを初期状態に戻す」

## 印刷

印刷は A4 横、基本は1ブロック1枚です。初期デモは A・B・C・D の計4枚になります。

`calculateResidentPrintHeight()` が、次の要素から必要な高さを人ごとに見積もります。

- 日勤と夜勤のうち、多い側の記録項目数
- 申し送りと毎日つづく大事なことの文字量
- 当日の予定と定期予定

通常は `compact` / `normal` / `large` / `x-large` の4段階で行高を配分します。20名満床でも、必要な記録欄を勝手に削りません。内容が極端に多く1枚に安全に収まらないときだけ、同じ文字サイズのまま2枚に分割します。

## 完全オフライン

- ビルド不要・依存パッケージなしの [`index.html`](index.html) 1ファイル
- 外部API、外部AI、CDN、外部フォント、解析タグを使用しない
- `fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` / Service Worker なし
- `file://` の直接起動と、静的Webホスティングの両方に対応
- 保存先は表示中のブラウザの `localStorage` のみ

`index.html` をダブルクリックするだけで起動できます。ブラウザや起動URLが変わると別の保存領域になるため、重要な変更はバックアップを保存してください。

## 保存キーとバージョン

- アプリバージョン: `2.0`
- データ構造バージョン: `9`
- デモseedバージョン: `1`
- 公開デモ専用保存キー: `handover_portfolio_demo_v2`

公開デモは独立した保存キーを使い、別の版の保存データを読み込みません。公開ページへ別用途のデータが意図せず混入することを防ぐためです。

## セキュリティとプライバシー

- Content Security Policy で `default-src 'none'` と `connect-src 'none'` を宣言
- `form-action` / `object-src` / `frame-src` / `worker-src` / `base-uri` も `none`
- すべての動的表示で `esc()` を通し、HTML・XSS注入を防止
- `hardenInputs()` と `MutationObserver` で、静的・動的入力欄の校正・入力予測等を無効化
- 復元前のバックアップ検証と prototype pollution 対策
- 壊れた保存データは退避し、無言で上書きしない

バックアップJSONには、ブラウザへ入力した内容がそのまま含まれます。この公開デモでは架空データだけを扱い、出力したファイルも適切に管理してください。

## テスト

追加のパッケージは不要です。

```bash
node tests/app.test.js
node tests/browser_check.js
```

Nodeテストはロジック、移行、検索、保存、バックアップ検証、XSS対策を確認します。ブラウザテストは Chrome または Edge で `file://` として実際に開き、入力、再読込、ブロック移動、予定、検索、印刷、セキュリティを確認します。

## 制約

- このデモは診断、治療判断、投薬判断、緊急度判定を行いません。
- 文章整形は入力済みの事実を読みやすく整えるローカル処理です。判断は専門職が行ってください。
- ブラウザのサイトデータを削除すると、バックアップしていない変更は失われます。
