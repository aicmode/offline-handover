# 申し送りメーカー（職場実運用版・完全オフライン）

介護・医療現場の「申し送り・勤務記録」を、**そのPCの中だけ**で作成・保存・検索・印刷するための単一HTMLアプリです。

- ファイルは [`index.html`](index.html) **1つだけ**（ビルド不要・インストール不要・依存パッケージなし）
- データはブラウザの localStorage にのみ保存
- **外部サーバー・外部AI・外部CDN・外部フォント・解析への通信は一切ありません**

> このリポジトリにはアプリ本体のコードだけを置きます。
> **実在する入居者・患者の個人情報や、実運用データは絶対に置きません。**
> 実運用のデータ入力は職場のPC内だけで行います。

> **GitHub Pages などで公開したページは「動作確認用」です。**
> 実在する入居者のお名前・部屋番号・申し送り・バイタルは入力しないでください。
> （入力内容は外部へ送信されませんが、そのブラウザの localStorage に残ります。）

---

## 使いはじめかた（職場PC）

1. `index.html` を職場PCの決まった場所（例：デスクトップの「申し送り」フォルダ）へ置く
2. ダブルクリックでブラウザ（Edge / Chrome）で開く
3. デスクトップかタスクバーへショートカットを作り、**毎日そこから開く**

インターネット接続は不要です。オフラインでも全機能が動きます。

> **毎日、同じPC・同じブラウザ・同じ場所のファイルから開いてください。**
> データはHTMLファイルの中ではなく、そのPCのブラウザ内に保存されます。
> 別のブラウザで開くと、別の保存場所になり「データが消えた」ように見えます。

## 画面（5つのタブ）

| タブ | できること |
| --- | --- |
| **入力** | 入居者の追加／毎日つづく大事なこと／本日の申し送り／記録・バイタル／予定の追加。すべて自動保存 |
| **入居者** | 入居者の追加・並べ替え・空床・退居／復帰、記録項目の設定、バックアップ |
| **予定** | 毎週くりかえす定期予定の登録、1回だけの予定の一覧・別紙印刷 |
| **印刷** | A4横の申し送り用紙のプレビューと印刷 |
| **さがす** | 現在の入居者と過去記録を全ユニット横断検索（日付・関連語・表記ゆれにも対応） |

## ユニット構成

| 区分 | 登録できる人数（上限） | 備考 |
| --- | --- | --- |
| 静養室 | 4 名 | 重症者などを一時的に管理する独立枠。画面上でも点線で区別 |
| ユニット2 | 34 名 | 余裕をもたせた上限 |
| ユニット3 | 30 名 | 同上 |
| ユニット4 | 30 名 | 同上 |
| ユニット5 | 30 名 | 同上 |

入居中の方を静養室へ一時的に移すときは、「入居者」タブの一覧にある **「いる場所」** から選び直します
（登録し直す必要はなく、過去の申し送り・記録・予定はそのまま残ります）。

新しく登録するときは、静養室・ユニット2〜5のどこでも「入力」タブ上部の **「〇〇へ追加」** から、
部屋番号・名前・毎日つづく大事なことを入力できます。従来どおり「入居者」タブから追加することもでき、
どちらも同じ入居者データとして自動保存されます。

上限を変えたいときは `index.html` の `UNIT_DEFS` の `max` を書き換えるだけです（1か所）。

```js
var UNIT_DEFS = [
  { id:1, label:"静養室",    max:4,  rest:true },
  { id:2, label:"ユニット2", max:34 },
  ...
];
```

## 印刷（A4横・1ユニット＝1枚）

- **静養室が0人のとき：ユニット2・3・4・5 の 4枚**
- **静養室に1人以上いるとき：静養室・ユニット2・3・4・5 の 5枚**（静養室が先頭）
- 静養室が0人へ戻れば、自動的に4枚構成へ戻ります
- 各ユニットは必ず別ページ。次のユニットの内容が前のページへ混ざりません
- 人数に応じて文字サイズが自動で段階変更されます（34名でも1枚に収まります）
- 入りきらない人がいる場合は、プレビュー下に「要確認」として名前が出ます（内容は勝手に削りません）
- 固定記入例・空床・退居は、人数にも印刷にも含まれません

## 毎週くりかえす予定（定期予定）

曜日と勤務帯を一度登録すれば、その曜日が来るたびに自動で用紙へ出ます。

| 勤務帯 | 出る用紙 |
| --- | --- |
| **日勤** | 実施する**その日**の用紙の【日勤】欄 |
| **夜勤** | 夜勤者が前もって確認できるよう、実施日の**前日**の用紙の【夜勤】欄 |

例：

- 毎週**月曜**の夜勤（BS測定） → **日曜**の用紙の夜勤欄
- 毎週**火曜**の夜勤 → **月曜**の用紙の夜勤欄
- 毎週**日曜**の夜勤 → **土曜**の用紙の夜勤欄

前日の計算は曜日の文字列ではなく**日付計算**で行うため、月末・年末年始・うるう年をまたいでも正しく出ます。

定期予定は「毎週◯曜日」という**ルールだけ**を保存し、表示する日付は毎回計算します。
そのため画面を開き直しても**予定が増えたり二重登録されたりしません**（長期運用でもデータが肥大化しません）。
1回だけの予定（受診・外出など）とは内部で別データとして区別しています。

## オフライン文章整形

短い入力や箇条書きを、申し送りとして読みやすい文章へ整えます。

```
発熱 38.0 カロナール服用 水分摂取
        ↓ 「文章を整える」
発熱38.0℃。カロナール服用。水分摂取。
```

- 単語だけ／短文／箇条書き／まとまりのない文章／長文に対応
- 辞書・キーワード解析・定型変換による**完全ローカル処理**（外部AI APIは使用しません）
- 転倒・誤嚥・全介助・2人介助・トロミ・アレルギー・禁忌などの語は**絶対に落としません**（落ちる場合は整形せず元の文章を返します）
- 無駄に長くしません（整形後が元より長くなる場合は整形しません）
- 「元にもどす」で整える前の文章へ戻せます

> 医学的判断・診断・投薬判断・緊急度判定は行いません。
> 入力された事実を読みやすく並べ直すだけです。判断は必ず職員・医療者が行ってください。

## 日付の自動更新と「さがす」

- 起動時の対象日はPC本体の「今日」です。開いたまま日付をまたいだ場合も、今日を表示中なら自動で翌日へ切り替わります
- 前日・翌日・カレンダーで別日を見ている間は、閲覧日を勝手に変えません
- 「さがす」は初期状態で静養室・ユニット2〜5の全体が対象です。名前・部屋番号から現在地を確認し、「この人を見る」で直接移動できます
- `2026`、`8月`、`2026年8月`、`2026/08`、`2026-08`、`14日` のような曖昧な記録日検索に対応します
- 全角／半角・大文字／小文字・ひらがな／カタカナ・余分な空白をローカルで正規化します
- 受診／病院、熱／発熱／体温、BS／血糖など、介護・医療現場で使う近い言葉を軽量な内蔵辞書で検索補助します
- 軽い誤字は自動置換せず、クリックできる候補として表示します

関連語は検索範囲を広げるためだけに使い、診断・治療提案・緊急度判定には使用しません。検索用の複製データは保存せず、検索時だけ組み立てます。

## 保存されない固定記入例

「入力」タブと「入居者」タブの両方にある「記入例を見る」を開くと、静養室・ユニット2〜5それぞれに異なる記入例が表示されます。固定記入例は実入居者カード／一覧表の外側にある説明専用UIです。

- 両タブとも `FIXED_EXAMPLES` という1つの静的定義を共有し、`renderFixedExample(hostId)` で描画します（二重管理をしません）
- DB・localStorage・バックアップJSONへ保存されません
- 人数・登録上限・印刷・予定・検索・過去記録・並び替えの対象になりません
- 入力欄や操作ボタンを持たず、編集・移動・退居・予定追加・バイタル入力はできません
- 入居者が0名の場所でも表示され、折りたたんだまま通常入力を始められます

### 旧版の見本入居者の整理

固定記入例へ置き換える前の版は、見本入居者（`sample-2`〜`sample-5`）を保存データへ自動作成していました。起動時とバックアップ復元時に `removeLegacySeedSamples()` が動き、**旧見本だと断定できるものだけ**を申し送り・記録・予定・定期予定ごと取り除きます。

断定に使う根拠は次のいずれかで、お名前や部屋番号が似ているだけのデータは削除しません。

- `demo === true`（見本を作るコードだけが付ける印。手動追加は必ず `demo:false`）
- `id` が `sample-数字` で、かつ 見本専用の `sample:{...}` を持つ、または 所属・部屋番号・お名前・毎日つづく大事なこと の4項目が旧見本と完全一致する

断定できないデータは削除せず `LEGACY_SAMPLE_KEPT` に記録し、人数・印刷・検索からは外したうえで一覧に残します。

## 入居者一覧の並び順

「入居者」タブの「並び順」から、手動順・部屋番号順・五十音順・追加した順・最近編集した順を選べます。選択は全場所共通で保存されます。

- 部屋番号・五十音・追加・最近編集は表示上だけのソートで、DBの配列順を書き換えません
- 五十音順は保存済みの名前文字列を日本語ロケールで比較します（読み仮名は保存しません）
- 追加した順は既存のDB配列順を利用します
- 最近編集した順は入居者ごとの軽量な `updatedAt` だけを利用し、旧データに日時がなければ配列順へフォールバックします
- ↑↓の手動操作は「手動順」を選んだときだけ有効です

一覧の入力欄は、**部屋番号を狭く・お名前を広く**取ります。部屋番号は「201」「静養1」程度で足りるのに対し、
氏名は入力中に全体が見えている必要があるためです。静養室・ユニット2〜5は同じ表を使うので幅は共通です。
狭い画面では表そのものが横スクロールし、レイアウトは崩れません。

## 記録する項目と設定メモリー

「入居者」タブの「設定する」から、入居者ごとに日勤・夜勤の記録項目（T・P・BP・SpO2・食事・BS・BW など）と
曜日を決めます。保存ボタンはなく、変更した時点で自動保存されます。

- **新しく登録した入居者は全項目OFFから始まります。** 必要な項目だけをONにする方式です
  （不要な項目を大量にOFFへ戻す手間をなくすため。内部で必ずONが要る項目はありません）
- 既存の入居者の設定はそのまま維持されます。アプリを更新しても勝手に全OFFにはなりません
- 日勤と夜勤は別々に持ちます（例：日勤 BP 月・木／夜勤 BP OFF）

### 一度使った曜日設定は覚えている

項目をOFFにしても、その項目に設定した曜日は入居者ごとに `rec.mem` として残ります。
後日また同じ項目をONにすると、前に使っていた設定（毎日／月・木 など）が戻ります。

- 覚えるのは項目1つにつき `{ e:毎日かどうか, d:[曜日] }` だけで、履歴や日別のコピーは作りません
- 職員が曜日を変えたら、その時点で新しい設定を覚え直します
- **OFFの項目は印刷にも入力画面にも出ません。**メモリーに残っていても表示・印刷の判定には使いません
- 削除した独自項目のメモリーは残しません
- 旧データにメモリーが無い場合だけ、いま保存されている設定を初回の覚え書きとして写します（現在の設定は書き換えません）

この追加は既存データに項目を足すだけなので、`DATA_VERSION` は 8 のまま変更していません。

## データの保存とアプリの更新

### 保存

- 保存先：ブラウザの localStorage（キー **`kaigo_handover_v2`**）
- 入力・修正はすべて自動保存（保存ボタンはありません）
- 保存できないときは画面上部に赤い警告が出ます
- 保存するのはテキスト・数値・日付・時刻のみ。画像・音声・動画は扱いません

### アプリを更新しても過去データを失わない設計

今後「職場で使用 → フィードバック → 自宅で修正 → 新しい index.html を職場PCへ導入」を繰り返す前提です。

- **保存キー `kaigo_handover_v2` は変更しません**（変更するとデータが読めなくなるため）
- データ構造を変えるときは `DB.v`（データ版数）を上げ、`migrate()` で旧形式を**非破壊的に**新形式へ補完します
- `migrate()` は既存の値を書き換えず、足りないものだけ補い、何度実行しても同じ結果になります

更新手順：

1. 念のため「バックアップを保存」
2. 古い `index.html` を新しい `index.html` で置きかえる（同じ場所・同じファイル名）
3. いつものブラウザで開く → 入居者・申し送り・記録・予定・定期予定はそのまま

**アプリを削除したり、ブラウザのデータを消したりする必要はありません。**

### アプリ版番号の運用

- `Ver1.0` は初回職場実運用版です
- 軽微な修正・改善では `Ver1.1`、`Ver1.2`、`Ver1.3` のように更新します
- 大きな仕様変更では `Ver2.0` のように更新します
- 変更する場所は `index.html` 内の `APP_VERSION` 1か所だけです
- `APP_VERSION` は画面表示用です。保存キー `kaigo_handover_v2` とデータ構造版数 `DATA_VERSION` は別管理のため、表示版番号だけの更新では変更しません

### バックアップ・復元

- 「入居者」タブ →「バックアップを保存」でJSONファイルをこのPCへ保存
- 「バックアップから戻す」で復元（実行前に、現在データの保存を確認します）
- ファイルが壊れている／形式が違う場合は**復元を中止し、いまのデータをそのまま残します**
- 危険な操作（完全削除・一括削除）はすべて確認ダイアログ付き

> **取扱注意：** バックアップファイルには氏名・部屋番号・申し送り・記録が含まれます。
> 保存場所・持ち出し・廃棄は施設の規定に従ってください。
> このリポジトリへは絶対にコミットしないでください（`.gitignore` で `*.json` を除外しています）。

## 完全オフライン

このアプリには、通信・送信を行う処理が**1件も実装されていません**。

- 送信系ブラウザAPI（通信・計測・ソケット等）の記述：**0件**
- 外部script / 外部stylesheet / 外部フォント / 外部画像 / 外部CDN：**0件**
- `http://` `https://` で始まるURL：**0件**
- Analytics / Telemetry：**なし**
- 外部API・外部AI・外部ライブラリ・npm等の依存：**なし**

これらは [`tests/app.test.js`](tests/app.test.js) が実行のたびに自動検査します。

さらに、万一コードへ通信処理が混入しても**ブラウザ側で止まる**ように、
`index.html` の先頭で Content-Security-Policy を宣言しています。

```
default-src 'none'; connect-src 'none'; form-action 'none'; base-uri 'none'; ...
```

`connect-src 'none'` により、通信API（fetch / XMLHttpRequest / WebSocket /
sendBeacon / EventSource）はブラウザに拒否されます。
`form-action 'none'` により、入力内容の送信先を作ることもできません。

### バックアップの Blob について

バックアップ保存では `URL.createObjectURL` を使いますが、これは
**このPCの中にJSONファイルを作って保存させるため**だけのものです（`blob:` はPC内のメモリ上のデータを指す仕組みで、通信ではありません）。
作成した URL は保存直後に `URL.revokeObjectURL` で破棄します。用途はアプリ内で1か所のみで、
テストが「1か所だけであること」「ダウンロードにだけ使っていること」を毎回検査します。

## ブラウザ側のクラウド処理を止める（spellcheck / 入力予測 / 翻訳）

アプリ自身が通信しなくても、**ブラウザの機能**が入力文字をクラウドへ送ることがあります
（Microsoft Editor の文章校正、Text Prediction、オートコンプリート、ページ翻訳など）。
そのため、次の防御を入れています。

| 対策 | 内容 |
| --- | --- |
| `<html spellcheck="false" writingsuggestions="false" translate="no" autocapitalize="off">` | ページ全体に継承させ、後から追加した欄も既定で保護される |
| 全入力欄への属性付与 | `spellcheck="false"` `autocomplete="off"` `autocorrect="off"` `autocapitalize="off"` `writingsuggestions="false"` |
| 共通処理 `hardenInputs()` | 画面を描き直すたびに全 `input` / `textarea` へ一括付与する |
| `MutationObserver` | 後から作られた入力欄も自動で保護する（付け忘れが起きにくい構造） |
| `data-gramm="false"` 等 | 校正拡張（Grammarly など）が本文を読むのを抑止 |

チェックボックス・ラジオ・ファイル選択など、文字を打たない欄には付けません。
すでに指定がある欄は上書きせず、そのまま尊重します。

> **これはアプリ側からの「お願い」です。** ブラウザやポリシーの設定が優先される場合があります。
> 職場PC側で行うべき設定は「[職場PC側で推奨する設定](#職場pc側で推奨する設定)」を参照してください。

## 入力文字が「コード」として動かないこと（XSS対策）

お名前・部屋番号・申し送り・毎日つづく大事なこと・予定・記録・検索文字に
`<script>` や `<img onerror=...>` のような文字列を入れても、**すべて文字として表示**され、
コードとしては実行されません。

- 画面へ出すユーザー入力はすべて `esc()` を通し、`<` `>` `&` `"` `'` を実体参照へ変換
- `insertAdjacentHTML` / `outerHTML` / `document.write` / `eval` は使用していません
- 入力した文字は**加工せずそのまま保存**されます（表示のときだけ安全化するため、データは欠けません）

---

## 保存データの安全性

- 保存キーは **`kaigo_handover_v2` 固定**（アプリを更新しても変更しません）
- 保存データが壊れていた場合、**上書きも削除もせず** `kaigo_handover_v2_broken` へ退避してから起動します
- 復元は形式検証を通ったファイルだけを受け入れ、途中で失敗したときは元のデータへ戻します
- 細工されたバックアップでもJavaScriptの土台（プロトタイプ）を汚染しないよう、危険なキー名だけを取り除きます

## 職場PC側で推奨する設定

**ここに書いた項目は、アプリのコードでは完全に制御できません。**
入力内容がクラウドで処理される可能性を下げるため、職場PCの設定でOFF（またはローカル処理）にすることを推奨します。

### Microsoft Edge

| 設定場所 | 項目 | 推奨 |
| --- | --- | --- |
| 設定 → 言語 | **文章作成の支援（Microsoft Editor）** | 「基本」またはOFF。「拡張（Microsoft Editor）」は入力文字がMicrosoftのサーバーで処理されるため使わない |

## 医療安全上の位置づけ

このアプリは申し送り・勤務記録を**整理して印刷する支援ツール**です。次のことは行いません。

- 診断・医学的判断
- 投薬判断・投与量判断・治療提案
- 緊急度判定の自動化

文章整形も、入力された事実を読みやすく整えるだけで、元の意味を勝手に変更・補完しません。
